# 開発フェーズ

## フェーズ0: 仕様ベースライン

目的:

- プロダクト、アーキテクチャ、データモデル、API、開発フェーズの基準を固定する。

完了条件:

- READMEから仕様書へリンクされている。
- MVPに含むものと含めないものが明記されている。
- バックエンド、フロントエンド、DB、認証、画像、モバイル展開方針が文書化されている。

## フェーズ1: 基盤構築

目的:

- 文書化されたスタックでアプリケーションの基盤を作る。

範囲:

- FastAPI、SQLModel、Alembic、PostgreSQL、uv、テスト、Lint/型チェックを含むバックエンドプロジェクト。
- React、TypeScript、Vite、生成APIクライアント運用を含むフロントエンドプロジェクト。
- ローカル開発用Docker Compose。
- 基本的なヘルスチェックエンドポイント。
- OpenAPIスキーマ生成。

完了条件:

- バックエンドとフロントエンドをローカルで起動できる。
- データベースマイグレーションを実行できる。
- テストを実行できる。
- フロントエンドからバックエンドのヘルスチェックエンドポイントを呼び出せる。

## フェーズ2: 認証とレシピMVP

目的:

- ログイン済みの個人ユーザーが実用できる状態にする。

範囲:

- ユーザー登録、ログイン、ログアウト、パスワードリセット、現在のユーザー情報、管理者ユーザー。
- レシピCRUD。
- 材料。
- 手順。
- タグ。
- レシピ一覧、詳細、作成、編集画面。
- 基本的なキーワード検索。
- お気に入り。

完了条件:

- ユーザーがログインし、自分のレシピを管理できる。
- 他ユーザーがそのレシピにアクセスできない。
- ユーザーがレシピを検索し、お気に入り登録できる。

## フェーズ3: 画像と調理記録

目的:

- レシピの視覚的な記憶と調理履歴を扱えるようにする。
- このフェーズの完了をもって、MVPスコープを満たした状態とする。

範囲:

- ローカル画像保存境界。
- レシピ画像のアップロードと削除。
- 調理記録CRUD。
- 調理記録画像のアップロードと削除。
- 関連する調理履歴を表示するレシピ詳細画面。

完了条件:

- ユーザーがレシピに画像を添付できる。
- ユーザーがレシピを作った日を記録できる。
- ユーザーが調理記録に画像とメモを添付できる。

## フェーズ4: 検索、UX、PWA準備

目的:

- 思い出しやすさと継続利用しやすさを改善する。

範囲:

- 検索とフィルターの改善。
- お気に入り中心の画面。
- 最近の調理履歴画面。
- レスポンシブレイアウト改善。
- PWA対応可否の評価。

完了条件:

- デスクトップブラウザとモバイルブラウザで快適に使える。
- ユーザーがキーワード、タグ、お気に入り、調理履歴から過去のレシピをすばやく見つけられる。

## フェーズ5: モバイルアプリ準備

目的:

- バックエンドの振る舞いを書き換えずに、ネイティブモバイルクライアントを計画できる状態にする。

範囲:

- モバイル利用に必要なAPI範囲の確認。
- モバイルクライアント向け認証・画像アクセス方針の安定化。
- Expo / React Nativeプロジェクト構成の評価。
- 互換性のあるTypeScript APIクライアントの生成。

完了条件:

- コアのプロダクトモデルを変えずに、既存APIを前提としてモバイルクライアントを計画できる。

## フェーズルール

- MVP完了前に公開共有を追加しない。
- MVP完了前に外部レシピURL解析を追加しない。
- 明示的に計画しない限り、MVP中にローカル画像保存をS3互換ストレージへ置き換えない。
- 2つ目のバックエンド依存管理ツールを導入しない。バックエンド依存管理はuvを使う。
- ブラウザ向けMVPが安定する前にネイティブモバイル実装を追加しない。
